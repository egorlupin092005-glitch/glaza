# Глаза

Приложение для настольного указателя с двумя сервоприводами: камера видит ладонь, программа вычисляет поворот и наклон, Arduino направляет маленькую палочку вслед за ладонью.

Настольный демонстратор компьютерного зрения: MediaPipe распознаёт ладонь, интерфейс показывает сопровождение, Arduino управляет двумя сервоприводами. Работает и без подключённой платы — для просмотра заданных углов. В комплекте исходники приложения, прошивки и тесты.

## Установка и запуск

Windows x64, Python 3.12 x64. После клонирования запустите **Install.cmd**: установятся зависимости и модель MediaPipe. Затем откройте **Start.cmd**.

1. Откройте **Start.cmd** двойным щелчком.
2. Нажмите **Включить камеру**. Обычно нужна камера № 0. Если изображение не появилось, выберите № 1.
3. Покажите открытую ладонь. На изображении должны появиться точки и линии руки.
4. Нажмите **Следовать за рукой**. Даже без Arduino на экране будут изменяться заданные углы и два схематичных указателя.

Камера включается кнопкой. Изображение обрабатывается на компьютере, не отправляется на сервер и не записывается. Интернет нужен только для первоначальной установки библиотек и модели.

## Подключение Arduino и SG90

В списке **Скетч на плате** выберите скетч, который загрузили через Arduino IDE.

| Скетч для открытия в IDE | Режим обмена |
|---|---|
| [servo_control.ino](arduino/servo_control/servo_control.ino) — копия присланного файла | 9600 бод. Программа передаёт строку с двумя углами через запятую. Статус «Порт открыт» означает, что Windows открыла выбранный порт. Ответов о приёме этот скетч не отправляет. |
| [glaza_pointer.ino](arduino/glaza_pointer/glaza_pointer.ino) — комплектный скетч | 115200 бод. Программа проверяет ответ платы и подтверждения команд. |

Для присланного скетча откройте в IDE файл из первой строки таблицы, выберите свою плату и порт, затем нажмите **Загрузить**. Закройте монитор и график последовательного порта. В «Глазах» включите камеру, выберите **servo_control**, этот же порт и **Подключить Arduino**. Движение включается кнопкой **Следовать за рукой**. Чтобы снова загрузить скетч из IDE, сначала нажмите **Отключить Arduino** в «Глазах».

Прошивка рассчитана на обычную **Arduino Uno или Nano на ATmega328P** и два позиционных SG90. Сервоприводы непрерывного вращения для этой программы не подходят.

| Подключение | Куда |
|---|---|
| Сигнал нижнего SG90 — поворот | D9 Arduino |
| Сигнал верхнего SG90 — наклон | D10 Arduino |
| Плюс питания обоих SG90 | Стабилизированное внешнее 5 В |
| Земля обоих SG90 | Минус внешнего питания |
| GND Arduino | Тот же минус внешнего питания |
| USB Arduino | Компьютер |

Для двух SG90 используйте отдельное питание 5 В с достаточным током, например 2 А. Общая земля обязательна. Плюс внешнего питания сервоприводов не соединяйте с выводом 5V Arduino, питаемой по USB. У SG90 обычно красный провод — питание, коричневый — земля, оранжевый — сигнал; проверьте маркировку своей модели.

1. Откройте в Arduino IDE нужный скетч из таблицы выше.
2. Для Uno R3 или классической Nano установите **Arduino AVR Boards** через менеджер плат и **Servo** от Arduino через менеджер библиотек. Кнопка **Проверить** собирает скетч для выбранной модели ещё до подключения платы.
3. Выберите свою плату и COM-порт, загрузите прошивку. Для некоторых Nano нужен вариант процессора **ATmega328P (Old Bootloader)**.
4. Закройте монитор последовательного порта и другие приложения, использующие этот COM-порт.
5. В «Глазах» включите камеру, нажмите **Обн.**, выберите COM-порт и нажмите **Подключить Arduino**.
6. Для `glaza_pointer` дождитесь ответа платы, для `servo_control` — надписи **Порт открыт**. После этого нажмите **Следовать за рукой**.

Для этого стенда в **glaza_pointer** задана исходная поза **0°/0°**. При открытии порта скетч сообщает приложению исходную позу и последнюю заданную команду. Центр кадра соответствует этой исходной позе, а смещение ладони задаёт отклонение от неё. Поля «Ход … −» и «Ход … +» задают величину отклонения в градусах. Доступный диапазон ограничивается ходом привода. В исходной позе 0° движение в сторону отрицательных углов недоступно. Для старого скетча без сообщения исходной позы приложение использует 90°/90°.

## Как устроено движение

Камера остаётся неподвижной. Центр ладони вычисляется по запястью и основаниям пальцев. Движение ладони по горизонтали управляет основанием, по вертикали — наклоном палочки. По умолчанию изображение зеркальное, как в привычном окне веб-камеры.

Эта версия следует за **положением ладони в кадре**. Она не измеряет поворот кисти в пространстве, расстояние до руки или точку пересечения палочки с рукой. Для такого поведения потребовались бы отдельная калибровка и другая модель управления.

Начальные настройки:

| Параметр | Значение |
|---|---|
| Нейтраль обоих приводов | 90° |
| Поворот | 45–135° |
| Наклон | 60–120° |
| Скорость изменения команды | 70°/с |
| Коэффициент отклика при 30 кадрах/с | 0,35 |
| Зона покоя у центра | 4% ширины/высоты кадра |
| Последовательный порт | 115200 бод |
| Частота отправки изменившихся команд | До 30 раз/с |

Настройки меняются при выключенной камере и сохраняются в `settings.json` при следующем запуске камеры. Если какая-то ось движется в противоположную сторону, включите её переключатель **Развернуть…**. Начинайте с узких пределов, затем увеличивайте их под механику своего стенда. Числа на экране показывают команды, а не измеренный угол вала.

**Стоп** прекращает сопровождение и удерживает текущую команду. **В центр** отключает сопровождение и плавно возвращает указатель в исходную позу скетча. При пропаже руки программа удерживает последнюю текущую команду. После появления руки сопровождение продолжается, если кнопка остаётся включённой. При разрыве соединения сопровождение отключается; потребуется подключиться заново.

Если закрыть программу или выключить камеру, данные перестают передаваться. Arduino продолжает удерживать последнюю полученную команду, пока остаётся питание. Кнопка «Стоп» не отключает питание приводов.

## Установка после переноса

Для новой установки нужен Windows x64 и Python 3.12 x64 с [python.org](https://www.python.org/downloads/windows/). Затем запустите **Install.cmd**, дождитесь `Glaza is ready` и откройте **Start.cmd**. Установка создаёт изолированную папку `.venv` и скачивает официальную модель MediaPipe с проверкой контрольной суммы.

Для переноса исходников копируйте папку `Glaza` без `.venv`, `.tools`, `__pycache__` и временных файлов сборки. На другом компьютере выполните установку заново. Окружение `.venv` на этом компьютере связано с установленным здесь Python Codex.

## Если что-то не работает

- **Камера недоступна:** закройте приложения, использующие её, проверьте разрешение Windows на доступ классических приложений к камере, попробуйте другой номер камеры.
- **Рука не находится:** улучшите освещение, покажите ладонь целиком; эта версия отслеживает одну руку.
- **Нет подключённых плат:** проверьте USB-кабель с передачей данных и наличие COM-порта в диспетчере устройств. Для совместимых плат может понадобиться драйвер их USB-преобразователя.
- **Arduino не ответила:** загрузите комплектную прошивку, проверьте выбранную плату/порт и закройте монитор порта Arduino IDE.
- **Приводы дёргаются или плата перезапускается:** проверьте внешнее питание и общую землю; затем уменьшите отклик и скорость в программе.
- **Окно не запускается:** запустите `Start.cmd`; сообщение останется в окне. Дополнительные ошибки записываются в `logs/glaza.log`.

## Файлы и проверка

- `app.py` — окно приложения.
- `tracking/detectors.py` — распознавание ладони.
- `tracking/motion.py` — сглаживание и команды приводам.
- `tracking/worker.py` — обработка кадров и управление соединением.
- `hardware/serial_controller.py` — протокол и подтверждения Arduino.
- `arduino/glaza_pointer/glaza_pointer.ino` — прошивка.
- `tests/` — проверки расчётов, соединения и запуска окна.
- `docs/Проверка.md` — фактически выполненные проверки и ограничения.

Запуск тестов: `.venv\Scripts\python.exe -m unittest discover -s tests -v`.

По запросу `HELLO` обновлённый скетч передаёт строку `POSE` с исходными и текущими заданными углами, затем `GLAZA 1`. Команда `S номер поворот наклон` получает ответ `OK номер поворот наклон`. Все строки заканчиваются LF. Прошивка допускает команды в обычном диапазоне 10–170° и на пути до исходной позы каждой оси. При сопровождении целевые углы ограничиваются настройками приложения. Если подтверждение команды не поступает за 0,7 секунды, приложение закрывает соединение. Плата подтверждает получение команды. Фактический угол вала системой не измеряется.
